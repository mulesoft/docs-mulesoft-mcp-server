[[add-governance-ruleset]]
== add_governance_ruleset

Add a governance ruleset from Anypoint Exchange to your project. To find the ruleset to add, use the search_asset tool to find a ruleset that matches an assetId, groupId, and version from user-provided criteria. The search_asset tool uses searchQuery=user criteria and assetFilters='ruleset' to return a ruleset meeting those criteria. Then, this tool adds the ruleset as a dependency to your project. Available only in Anypoint Code Builder.

[[configure-agent-network-yaml]]
== configure_agent_network_yaml

Modifies an agent network project YAML file. The tool can replace placeholder YAML created from a template with values generated from user prompts and guided setup (mode='configure'). Or, the tool can make minor changes to a preconfigured agent network YAML file (mode='edit'). The LLM determines the appropriate mode value from user prompts and guided setup. Available only in Anypoint Code Builder.

[[create-agent-network-project]]
== create_agent_network_project

Create and scaffold an agent network project with a name and location you specify. Available only in Anypoint Code Builder.

[[create-and-manage-assets]]
== create_and_manage_assets

Create an asset in Anypoint Exchange, update some Anypoint Exchange asset properties without republishing the asset, and delete an asset in Anypoint Exchange. Asset properties are the asset name, description, icon, contact name, and contact email.

[[create-and-manage-metadata]]
== create_and_manage_metadata

Define metadata for a flow component, attach metadata to Mule flow components, and update existing metadata. To define metadata, provide the Mule configuration file URI and sample data or schema. To apply metadata, specify existing metadata types. To update metadata, provide new schema or sample data. Available only in Anypoint Code Builder.

[[create-api-spec-project]]
== create_api_spec_project

Create and scaffold an API spec or fragment project. You can specify the project name, location, and spec language (RAML, OAS, etc.).

[%header,cols="1,3,1"]
|===
|Parameter |Description |Required?

|projectName
|Unique name of the project. This name is used as the API spec title in Exchange, the name of the spec file, and the name of the project's root directory.
|Yes

|projectPath
|Parent location of the project. The default is the parent folder of the current workspace. The project will reside in a subfolder of projectPath.
|No

|isApiEnabledForTopicsAndActions
|Whether the project is enabled for topics and agent actions through MuleSoft for Agentforce: Topic Center. Only OAS 3.0 is supported. Default is false.
|No

|language
|Language of the API spec. Valid values: `oas`, `oas-components`, `raml`, `raml-fragments`, `json-schema`, `avro-schema`, `evented-api`.
|Yes

|languageVersion
|If language=oas or oas-components, valid values are `2.0` and `3.0`. If language=raml or raml-fragments, valid values are `1.0` and `0.8`. If language=evented-api, valid value is `2.6`.
|Yes

|fragmentType
|Required when language=raml-fragment. Valid values: `trait`, `resource-type`, `library`, `overlay`, `extension`, `type`, `user-documentation`, `example`, `annotation-type`, `security-scheme`.
|No

|format
|Valid values: `json`, `yaml`, `avsc`. If language=oas or oas-components, default is yaml.
|No

|===

[[deploy-agent-network]]
== deploy_agent_network

Deploy an agent network instance to a runtime environment. Specify the project path, target environment, deployment target, and Managed Flex Gateway configuration for deployment. Prerequisites: Managed Flex Gateway, a business group, and the agent network project contains a valid `exchange.json` file. Available only in Anypoint Code Builder.

[[deploy-mule-application]]
== deploy_mule_application

Deploy your application to CloudHub 2.0 or Runtime Fabric and run it. You can deploy from a local project or Anypoint Exchange asset. This tool supports security, high availability, and performance optimization deployment options.

[[get-flex-gateway-policy-example]]
== get_flex_gateway_policy_example

Get a Flex Gateway policy example to help you configure your Rust source code. You can get example policies that manipulate a request's header and body, make HTTP calls to external services, share data between requests and responses, reject requests, and perform sleep operations.

[%header,cols="1,3,1"]
|===
|Parameter |Description |Required?

|feature
|Valid values: `header_manipulation` (CRUD for request/response headers), `body_manipulation` (read or update request/response body), `http_call` (HTTP call to external service), `control_flow` (stop request flow and generate custom response), `request_data` (share data between requests and responses), and `timer` (perform sleep operations).
|Yes

|===

[[get-platform-insights]]
== get_platform_insights

See how your organization leverages the Anypoint Platform through usage and operational insights. These include:

* Usage trends for apps, such as flow count, message counts, and data throughput by business group and environment. Usage trends are for the current month. If it's early in the month, you get usage for the last full month.
* API and app call volume across consumers for last 7 days.
* API and app performance metrics such as errors and latency for last 7 days.

[%header,cols="1,3,1"]
|===
|Parameter |Description |Required?

|entityName
|Name of the application or API.
|No

|entityType
|Type of entity. Valid values: `application` and `api`.
|No

|includeFlows
|Whether app usage trends for flows are included. Default is false.
|No

|includeMessages
|Whether app usage trends for messages are included. Default is false.
|No

|includeDataThroughput
|Whether app usage trends for data throughput are included. Default is false.
|No

|includeErrorCount
|Whether error counts from apps and APIs are included. Default is false.
|No

|includeCallVolume
|Whether call volume from apps and APIs are included. Default is false.
|No

|includeLatency
|Whether P99 latency is included in the response time. Default is false.
|No

|latencyPercentile
|If includeLatency=true, this parameter contains the percentile to measure latency. Valid values: `P99`, `P95`, `P90`, `P75`. Default is P99.
|No

|===

[[validate-api-against-ruleset]]
== validate_api_against_ruleset

Validate an API specification in your project against governance rulesets or rules that you specify. If you specify all rulesets, the tool uses an empty 'rules' parameter to validate all rulesets. Similarly, if you specify no ruleset, the tool uses an empty `rules` parameter. To find rules or rulesets that you specify, this tool calls the `list_governance_rulesets` tool. Available only in Anypoint Code Builder.

[[validate-project]]
== validate_project

Validate the current project. For example, an API spec or an agent network project. This tool doesn't validate against API Governance rulesets. To validate against those rulesets, use the `validate_api_against_rules` tool. Available only in Anypoint Code Builder.
